# A/B Test (Traffic Split) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** split one live URL between 2–4 `funnel@v` variants with sticky edge cookies, show per-variant numbers, switch to the winner by hand.

**Architecture:** `experiments` + `experiment_arms` (migration 013); the route row keeps arm 0; `syncHost` adds `exp` + `arms` to the KV route; the edge picks the arm (cookie or weighted random) and serves it as the target; stats from ClickHouse `events` (visitors) and Postgres `checkouts`/`transactions` (purchases, revenue) plus a z-test; HTTP, CLI, SPA, demo e2e.

**Tech Stack:** Node ESM, Fastify 5, Postgres 17 + ClickHouse (Testcontainers via colima: `export DOCKER_HOST=unix://$HOME/.colima/default/docker.sock`), Vitest, Cloudflare Worker (vitest-pool-workers), React SPA, Playwright demo e2e.

**Spec:** `ifunnel/docs/specs/2026-10-17-ab-test-design.md` (the authority).

**Worktree:** `/Users/daothinh/ikf-platform-ab`, branch `feat/ab-test` (base `feat/custom-domains`).

**Ruling P0:** not scratch-verified; tasks give interfaces, files and tests; implementers write the code test-first in the neighbouring style.

## Global Constraints

- The SDK bundle (`packages/sdk`) must not change (byte-identical build); budget test stays green.
- Logs: no email, `user_id`, token, `err.message` of SQL/third-party errors, SQL params, IP or UA. The edge logs `err.name`, never the cookie.
- Lock order: `domains` (FOR UPDATE, host asc) → `funnels` (FOR SHARE). Never a domain lock after a funnel lock.
- Audit without PII; `audit(c, actor, action, target, details, {app_id})`.
- The demo must not change `services/`, `workers/`, `packages/`.
- Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no bare `git stash`.
- SPA/CLI copy in Vietnamese; error codes English.

## Review Focus

1. A visitor with a cookie from a stopped experiment, or for an arm that no longer exists → reassigned, never a 500.
2. Weights at the boundaries (1/99, 33/33/34) → the random pick covers each arm exactly its share (`r ∈ [0,100)` cumulative).
3. Two starts on one prefix at once → one experiment, the other `409 experiment_running`.
4. A publish to the prefix during an experiment → `409 experiment_running`, nothing changed.
5. ClickHouse down → the experiment page still loads with purchases/revenue and "analytics unavailable".

### Task 2: Stats

**Files:** Create `services/core-api/src/experiments/stats.js`; Test `services/core-api/test/experiments-stats.test.js` (Postgres + ClickHouse containers, following the existing analytics tests' setup — find them with `ls services/core-api/test | grep -i analytic`).

**Interfaces:**
- Consumes: the analytics ClickHouse client (`src/analytics/clickhouse.js`; reuse its query function and settings `max_execution_time`, its unavailable error), `getExperiment`.
- Produces: `experimentStats({ pool, ch, log }, experiment, { now })` → `{ arms: [{arm, funnel, v, weight, visitors|null, purchases, cr|null, revenue:[{currency, amount_minor}], rpv:[{currency, amount_minor_per_visitor}]|null, confidence|null, also_live_at:[prefix]}], analytics: 'ok'|'unavailable' }`.
  - ClickHouse: one query `SELECT funnel, v, uniqExact(sid) FROM events WHERE host = {host:String} AND received_at >= {from:DateTime64(3)} AND received_at < {to:DateTime64(3)} AND (funnel, v) IN (…) GROUP BY funnel, v` with bound parameters (never string-built values).
  - Postgres: completed checkouts per (funnel_id, v) with `created_at` in window and `lower(split_part(split_part(client_url, '://', 2), '/', 1)) = host` (strip a `:port` too); revenue = each checkout's earliest transaction with status `paid` or `completed` (check which statuses the billing code treats as paid — grep `transactions` in `src/billing`) summed per currency.
  - `zTest(c0, n0, c1, n1)` → p-value (two-sided, pooled), exported and tested against a worked example (e.g. 100/1000 vs 130/1000 → z ≈ 2.09, p ≈ 0.037); confidence = round((1 − p) × 100, 1); null when n0 or n1 < 100 or c0 + c1 < 5, and for arm 0.
  - `also_live_at`: other prefixes of the same host whose route version is that arm's version.
